# Research: Маркетплейс тапсырыстарын басқару

## 1. Жоба туралы

**Жоба атауы:** Маркетплейс тапсырыстарын басқару  
**Зерттеу нысаны:** Kaspi.kz (Kaspi Магазин)  
**Бағдарламалау тілі:** Java 21  
**Бағыты:** Объектіге бағытталған бағдарламалау (OOP)

## 2. Зерттеудің мақсаты

Маркетплейстегі тауарларды сату, себетке қосу, тапсырыс рәсімдеу және төлем жасау процестерін зерттеу. Сонымен қатар клиенттің кредиттік скорингіне байланысты кредит пен рассрочка мүмкіндіктерін қарастыру.

## 3. Жүйенің негізгі мүмкіндіктері

- Сатушылар мен тауарларды сақтау.
- Клиенттің себетін басқару.
- Тапсырыс құру және жалпы соманы есептеу.
- Тапсырыс статусын өзгерту.
- Клиенттің кредиттік скорингін тексеру.
- Кредит немесе рассрочка арқылы төлеу.

## 4. Негізгі Java кластары

| Класс | Қызметі |
|---|---|
| `Customer` | Клиент туралы ақпарат |
| `Seller` | Сатушы туралы ақпарат |
| `Product` | Тауар мәліметтері |
| `Cart` | Тауарларды себетке жинау |
| `Order` | Тапсырысты басқару |
| `OrderItem` | Тапсырыстағы тауар позициясы |
| `OrderStatus` | Тапсырыс статустары |
| `CreditScoringService` | Клиент скорингін тексеру |
| `Payment` | Төлемнің негізгі класы |
| `CreditPayment` | Кредит төлемі |
| `InstallmentPayment` | Рассрочка төлемі |

## 5. Кредиттік скоринг жүйесі

Клиенттің кредиттік балына байланысты төлем мүмкіндігі анықталады.

- **750–1000 балл:** кредит және рассрочка.
- **650–749 балл:** тек рассрочка.
- **0–649 балл:** кредит пен рассрочка қолжетімсіз.

Бұл баллдар — оқу жобасына арналған шартты көрсеткіштер, Kaspi-дің нақты талаптары емес.

## 6. Кластар арасындағы байланыс

Бір сатушы бірнеше тауар ұсына алады. Клиент себетке бірнеше тауар қосып, тапсырыс рәсімдейді. Тапсырыс бірнеше тауар позициясынан тұрады. Төлем түрі клиенттің скоринг нәтижесіне байланысты анықталады.

Зерттеу нәтижесінде маркетплейс тапсырыстарын басқару жүйесінің құрылымы анықталды. Жоба клиенттерді, тауарларды, тапсырыстарды және төлемдерді басқаруға арналған. Қосымша кредиттік скоринг, кредит және рассрочка мүмкіндіктері қарастырылды.
